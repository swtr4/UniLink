UC09: Submit Proof of Completion

Goal: To allow a Job Seeker to upload evidence of work, update job status, and notify the poster.
Actor: Job Seeker

Preconditions
The User is logged into the UniLink system.

The User is assigned to a job with the status "In Progress."

Basic Flow
1. Actor: Selects the "My Active Jobs" section from the menu.

2. System (Boundary - MyActiveJobs Page): Requests the list of active jobs for the user.

3. System (Control - JobController): Retrieves the specific job data from the Entity (Job) and displays them on the Boundary (MyActiveJobs Page).

4. Actor: Selects the specific job to submit proof for.

5. System (Boundary - JobDetails Page): Displays the details and provides the "Submit Proof" button.

6. Actor: Clicks the "Submit Proof" button.

7. System (Boundary - Proof Submission Form): Opens the submission interface.

8. Actor: Enters a text summary, uploads a file, and clicks "Submit."

9. System (Control - SubmitProof Handler): Receives the input and passes the file to the Control (FileValidator).

10. System (Control - FileValidator): Validates that the file is in a supported format (Image or PDF).

11. System (Control - SubmitProof Handler): * Creates and saves a new Entity (Proof) record.

- Updates the Entity (Job) status to "Pending Approval."

- Triggers the Boundary (Notification Service) to alert the Job Poster.

12. System (Boundary - Confirmation Message View): Displays "Proof submitted successfully."

Alternative Flow 1: Incorrect File Format
10.a.1: The Control (FileValidator) identifies an unsupported format (e.g., .exe).

10.a.2: The Control (SubmitProof Handler) sends an error signal back to the UI.

10.a.3: The Boundary (Proof Submission Form) displays the message: "Invalid file format. Please upload a PDF or Image."



UC10: Submit Peer Review
Goal: To allow a user to rate and provide feedback for another user, updating their reputation score.
Actor: User (Student, Professor, or Company)

Preconditions
- The User is logged into UniLink.

- A Job or Activity interaction is marked as "Completed."

- No review has been submitted for this specific interaction yet.

Basic Flow
1. Actor: Navigates to "Pending Reviews" via the Boundary (UserProfile Page).

2. System (Control - Review Controller): Retrieves items requiring review from the Entity (Job/Activity).

3. System (Boundary - Pending ReviewsPage): Displays the list of reviewable items.

4. Actor: Selects the specific item/user to review.

5. System (Boundary - ReviewForm): Displays the 1-5 star selector and mandatory comment field.

6. Actor: Selects a rating, enters a comment, and clicks "Submit."

7. System (Control - SubmitReview Handler): Sends the data to the Control (InputValidator).

8. System (Control - InputValidator): Confirms that both the rating and comment are present.

9. System (Control - SubmitReview Handler): * Saves the data into a new Entity (Review).

- Requests a calculation update from the Control (Rating Calculator).

10. System (Control - Rating Calculator): Recalculates the average score and updates the Entity (UserProfile) of the target user.

11. System (Boundary - Notification Service): Sends a "New Review" notification to the target user.

12. System (Boundary - Confirmation Message): Displays success message: "Your review has been submitted."

Alternative Flow 1: Missing Required Comment
8.a.1: The Control (InputValidator) detects the comment field is empty.

8.a.2: The Control (SubmitReview Handler) returns an error state to the UI.

8.a.3: The Boundary (ReviewForm) highlights the field and displays: "Please provide a comment describing your experience."
